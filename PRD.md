Product Requirements Document: TahtaKilit MVPProduct OverviewApp Name: TahtaKilit (Alternative: Nöbetçi)Tagline: Simple, Un-bypassable Smart Board Security & Application Tracking SystemLaunch Goal: Bulletproof operation on interactive smart boards within a single target school environment, blocking all student intrusion vectors while preserving a low-friction entry point for educators.Target Launch: 2 Days for Local Demo / 1 Week for Production Release.Who It's ForPrimary User: School TeachersThis user base encompasses teachers across a broad spectrum of technological literacy, including senior faculty members. They do not want to interact with complex software interfaces, memorize administrative keys, or wait for long boot cycles during limited class hours.Their Current Pain:Students opening unauthorized games, browsers, or inappropriate media on smart boards between classes.Complex security applications that require typing long passwords on non-responsive touchscreen keyboards.Fear of being locked out of their own teaching environment if a security system malfunctions or fails to recognize them.What They Need:An instant "Look and Unlock" mechanism (Facial Verification).An absolute safety valve / administrative fallback method if lighting conditions or facial capture angles fail.A user interface that stays completely out of the way once authorized.Example User Story"Meet Ahmet Öğretmen, a history teacher who admits he isn't very comfortable with modern computers. He enters a noisy classroom to begin his lecture. The smart board is securely locked with a clear, non-intimidating screen. He glances at the camera, the system recognizes his face within 3 seconds, unlocks instantly, and minimizes to the background. Ahmet teaches his lesson without thinking about the software. At break time, he hits a single conspicuous button, the system locks back down, and he leaves the classroom knowing students cannot access the operating system."The Problem We're SolvingStandard kiosk strategies (such as running maximized windows or top-level UI forms) are trivial to bypass on interactive touchscreens via basic edge swipes, virtual keyboard triggers, or system hotkeys. Without deeper OS-level control, smart boards remain highly vulnerable to tampering.Furthermore, school administrations lack visibility into which desktop applications are actively running throughout the school day, making software usage tracking impossible.Why Existing Solutions Fall Short:Standard Windows Passwords: Teachers forget them or accidentally type them visibly in front of students.Basic Fullscreen Overlays: Can be bypassed easily using classic shortcut patterns (Alt+F4, Win+D, or tapping long enough to invoke sticky keys/context menus).User JourneyDiscovery → First Use → SuccessDeployment PhaseThe administrator installs the compiled TahtaKilitCore.exe application on the target smart board, executes the Registry configuration layer, and registers the local teachers' baseline photos into the secure localized models/ directory.The Daily Loop (Lock Screen State)The smart board boots directly into the customized TahtaKilit shell interface instead of loading the classic Windows desktop explorer environment.The system displays a clean, high-contrast lock window reading: "SİSTEM KİLİTLİ - Lütfen Kimlik Doğrulaması Yapın".Authentication Event (The "Aha!" Moment)The teacher stands in front of the smart board webcam.The background processing engine scans the matrix frame against memory cache indices.On a positive match, the lock screen disappears, granting access to the underlying apps.Fallback Event: If environmental issues prevent a fast face match, the administrator/teacher invokes a secure hotkey combination to input an explicit local verification override string.Session Activity & Re-lockingThe teacher conducts the lesson normally. An independent concurrent background thread captures the foreground active application processes (.exe filenames and window titles) silently.When the class finishes, the teacher hits the "Oturumu Kapat ve Tahtayı Kilitle" layout button. The system clears active memory spaces and transitions seamlessly back to the deep kiosk lock state.MVP FeaturesMust Have for Launch1. Local In-Memory Face Matrix IdentificationWhat: Uses OpenCV and a low-tolerance mathematical vector analysis cache to rapidly identify registered teacher profiles without requiring real-time external network/cloud API roundtrips.User Story: As a teacher, I want the system to authenticate my face automatically within seconds so that I don't waste valuable lecture time typing credentials.Success Criteria:[ ] Successfully distinguishes between enrolled teacher profiles and unknown students.[ ] Unlocks the main screen environment in less than 3 seconds under proper alignment.[ ] Strict verification validation parameters block standard printout/photo bypass attempts.Priority: P03. Core Architecture State-Machine InterfaceWhat: A lightweight, thread-safe dual-window Python interface utilizing Tkinter abstraction layers to safely transition between the absolute lock layout and the teaching control view.User Story: As a teacher, I want a clean, simple dashboard so that I can re-lock the smart board with a single tap before leaving the classroom.Success Criteria:[ ] The Lock view enforces permanent fullscreen (-fullscreen True) and top-level visibility (-topmost True).[ ] Tkinter structural event handlers trap local hotkeys (Alt-F4) and return an absolute structural break to halt the execution chain.Priority: P04.
